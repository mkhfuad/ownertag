# Deploying OwnerTag to Production — Non-Technical Guide

Total time: ~45 minutes. Cost: ~€15–25/month to start. No terminal needed after step 1.

---

## Step 1 — Put the code on GitHub (10 min)

GitHub is where your code lives; the hosting service reads it from there.

1. Create a free account at **github.com**.
2. Click **+ → New repository** → name it `ownertag` → set it to **Private** → Create.
3. Easiest upload for non-developers: install **GitHub Desktop** (desktop.github.com), sign in, choose **Add local repository**, pick the folder `~/Claude/Projects/OwnerTag/ownertag-app`, then click **Publish repository** (keep "private" ticked).

> The `.gitignore` file already excludes your local `.env` (secrets) and `node_modules` — nothing sensitive gets uploaded.

## Step 2 — Deploy on Render (10 min)

Render is a hosting service that runs the app, the database, and Redis for you — in **Frankfurt**, which keeps your data in Germany.

1. Create an account at **render.com** (sign up *with GitHub* — one click).
2. Click **New + → Blueprint**.
3. Select your `ownertag` repository. Render finds the `render.yaml` file and shows the plan: one web service, one Postgres database, one Redis.
4. Click **Apply**. Wait ~5 minutes while everything builds.
5. Your shop is now live at `https://ownertag-XXXX.onrender.com` (Render shows the exact URL). The database schema installs itself on first start.

Secret keys (encryption, admin) are **auto-generated by Render** — you never handle them.

## Step 3 — Your own domain (15 min)

1. Buy a domain (e.g. `ownertag.de`) at a registrar like **INWX**, **united-domains**, or **Namecheap** (~€10–15/year).
2. In Render: your web service → **Settings → Custom Domains → Add** → enter your domain. Render shows you two DNS records.
3. At your registrar, paste those DNS records (they have help pages for exactly this).
4. Back in Render → **Environment** → change `BASE_URL` to `https://yourdomain.de`. HTTPS certificates are automatic.

## Step 4 — Make SMS codes real (Twilio, 20 min)

Right now, activation codes only print to a developer console — real users can't receive them. Twilio sends real SMS:

1. Create an account at **twilio.com**, complete business verification.
2. Buy 1–2 **German phone numbers** (Phone Numbers → Buy a Number → Germany).
3. From the Twilio Console dashboard, copy the **Account SID** and **Auth Token**.
4. In Render → your service → **Environment**, fill in:
   - `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN`
   - `TWILIO_RELAY_NUMBERS` = your German numbers, e.g. `+4930123456,+4930654321`
5. Click **Save** — Render restarts the app automatically.

From this moment activation, login, and masked calls work with real phones. WhatsApp and email channels can be added later the same way (their variables are already waiting in the Environment tab).

## Step 5 — Before you tell the public (legal, Germany)

Not optional in Germany:

- **Impressum** and **Datenschutzerklärung** pages — the footer links exist but are placeholders. Services like **eRecht24** generate compliant texts; a lawyer review is recommended.
- **AGB + Widerrufsbelehrung** (terms + 14-day cancellation) for the shop.
- If you sell physically: **Verpackungsgesetz/LUCID** registration for packaging.

## Day-to-day operations

- **See orders:** open `https://yourdomain.de/api/admin/orders?key=YOUR_ADMIN_KEY` (find `ADMIN_KEY` in Render → Environment). Bookmark it.
- **Fulfill an order:** every order in that list includes a `print_url` — open it and the system mints exactly that order's tags and shows a print-ready page (3.5×2 in, one label per page). Print on waterproof sticker paper (⌘P), stick, ship, then mark the order `shipped`. Re-opening the URL reuses the same tags, so reprinting is safe.
- **Create tags for printing:** Render → your service → **Shell** tab → type `node scripts/mint-tags.js 100` → copy the list of URLs for your sticker printer.
- **Update the site:** change files locally → in GitHub Desktop click **Commit** then **Push** → Render redeploys automatically in ~3 minutes.
- **Logs:** Render → your service → **Logs** — if something breaks, copy the red lines to Claude.
- **Backups:** Render Postgres includes daily backups on paid plans.
